# 1.26.0 游戏内验收

以下是待执行的验收步骤，不是已通过的测试报告。主机与客机均安装相同版本及依赖，保留各自的 BepInEx/LogOutput.log。不要同时安装多个 MinecraftFoods DLL。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| F10 面板 | 游戏中按 F10，编辑、保存、关闭，再按 Esc 关闭 | 鼠标可操作；点击控件不吃东西、不移动视角；关闭后控制恢复，世界继续运行 |
| 跟随语言 | 客户端切换中文、英文、日文 | 名称、效果、烹饪预览、计时和面板同步更新 |
| 手动语言 | F10 选择 en / ja / zh-CN / Auto 并保存 | 手动覆盖生效；Auto 恢复跟随客户端 |
| 文件修改 | 编辑插件目录 settings.cfg，然后 F10 重新载入 | 有效值生效；非有限数值不会破坏掉落表 |
| 禁用食品 | 房主将指定箱子的某食品倍率设为 0 | 后续该池没有该食品；其他类型箱子不受影响 |
| 权重极值 | 房主将某档设为 0、所有档设为 0、占比设为 1 分别测试 | 单档禁用；全禁用回退原版；有启用食品时占比1为纯模组食品 |
| 客机权限 | 客机打开 F10 | 掉落设置只读，显示和语言可改 |
| 版本 | 启动游戏，查看 BepInEx 及 MinecraftFoods-diagnostics.txt | 显示 1.26.0；注册 34 食物；记录普通、诅咒、小丑池占比及各稀有度占比 |
| 默认信息 | 拿苹果、河豚、金苹果、炖菜 | 回复与风险可读，不遮住主要操作提示 |
| 可选显示模组 | 分别启用／停用信息增强模组后启动 | 食物说明可显示，效果倒计时独立存在，无重复说明 |
| 详细信息 | 开启 DetailedFoodInformation | 额外展示烧焦／烧毁次数；随机分支默认完整展示，比较三语言排版 |
| 剩余次数 | 连吃蛋糕，放下再捡起，交给队友 | 剩余次数逐次减少且双方一致，最后一次只消耗一次 |
| 生熟变化 | 手持生肉烹饪，放进物品栏再取出 | 名称、贴图、回复同步改变，物品不因变熟掉落 |
| 烧焦烧毁 | 将食物加热到各自阈值 | 预览与实际一致，烧毁后不能吃或喂食 |
| 持续毒 | 食用河豚，再喝蜂蜜或牛奶 | 出现持续毒；解除后计时消失且毒不再由该计时增加 |
| 金苹果 | 食用普通／附魔金苹果 | 无敌结束后睡意在6／12秒内升满，实际昏睡后计时并维持6／12秒；结束撤去高于原有基线的睡意，其他状态可能延迟苏醒 |
| 金苹果叠加 | 附魔金苹果后吃普通金苹果；后遗症期间再吃 | 强效果不被短效果截断；后遗症在当前无敌结束后开始，倒计时一致 |
| 牛奶 | 在无敌中、等待后遗症时、后遗症中喝牛奶 | 护盾、待触发后遗症及持续效果清除，不在稍后重新出现 |
| 混合回复 | 炖菜恢复后吃金苹果、反向再试 | 同类持续回复刷新，不累加多份恢复总量 |
| 死亡复活 | 带毒／金苹果状态死亡后复活 | 旧计时不在复活后继续施加 |
| 音效 | 自吃、取消、喂食；中途丢弃或死亡 | 持有者食用期间播放、停止时关闭，无吃完再补播；远端空间声音不属于本版功能 |
| 联机喂食 | 房主喂客机、客机喂房主，各试普通食品和毒食物 | 效果只作用在被喂者，每次仅消耗一次，持有者状态不误改 |
| 紫颂果 | 空旷区、狭窄区、危险地形附近食用 | 仅在水平 30 米内找到候选落点才传送；找不到时留原地、不计感染或代价，双方位置同步；成功后随机25点饥饿或15点孢子；成功间隔不超过120秒时累计，第4次5秒后僵尸化，提前喝牛奶解除 |
| 箱子 | 分别开普通／诅咒／小丑箱，多局观察 | 随机食物分布与配置相符；不以少量箱子没有出货判定失败 |
| 切场景／重连 | 有临时效果时切换场景或离开再进 | 无报错、无旧计时错用到新角色；重新检查掉落诊断 |

现有 `--mcfoods-audit` 是可选的游戏运行审计入口，会运行后退出游戏；它只能检查注册、烹饪和掉落表，不替代以上实际联机测试。未经用户要求不要自动启动或关闭其游戏。
