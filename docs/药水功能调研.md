# Minecraft 药水后续开发：PEAK 代码调研

基于本机 PEAK 的 Assembly-CSharp 反编译代码。仅调研，没有在 1.25.0 中添加药水或调用以下变身接口。

## 僵尸化：存在原生实现，但会让玩家死亡

- `Character.Zombify()`：控制台测试入口，通过 Photon RPC 调用 `RPCA_Zombify`。
- `Character.RPCA_Zombify()`：房主生成 `MushroomZombie_Player`，调用 `MushroomZombie.RPC_Arise(sourceCharacterPhotonID)`，并设置 zombified 标志。
- `MushroomZombie.RPC_Arise()`：复制原玩家肢体位置和外观关联，调用原玩家的 `FinishZombifying()`，随后进入 AI 的 WakingUp 状态。
- `Character.FinishZombifying()`：设置死亡、昏迷状态，清空额外体力，掉落物品和背包，触发死亡事件及终局检查。
- `CharacterAfflictions.willZombify`：孢子达到 0.5（50 点）且 `Ascents.shouldSpawnZombie` 开启时具备感染转化条件；并非加一次孢子就会立即变身。
- `Affliction_ZombieBite(totalTime, delay, statusPerSecond)`：延迟后持续增加孢子；孢子降到 2.5 点以下会结束。

因此，原生流程可作为“感染／死亡后生成僵尸”的参考，不能直接承诺喝药后变成玩家可操控的僵尸。可操控、可恢复的僵尸药水应独立设计外观、状态与恢复过程，保留玩家网络所有权及背包，避免调用 FinishZombifying。

## 变大／变小：未找到现成玩家药水接口

已检索 Character、CharacterData、CharacterRagdoll、CharacterMovement、全部 Affliction 类以及 shrink/enlarge/scaleplayer/sizeMultiplier 等名称，没有找到可直接调用的玩家体型效果或 RPC。这是本次代码搜索结论，不是断言游戏任意资源中都不存在类似行为。

存在 `ItemScaleSyncer.currentScale`、`ApplyScale` 和 `RPC_SyncScale`，但该组件依赖 Item，是物品缩放实现，不能直接加到玩家身上。`CharacterRagdoll.massMultiplier` 调整质量，也不等同于体型。

后续玩家体型药水需要同步处理：

1. 保存和恢复玩家模型、骨骼、碰撞体与关节的原始参数。
2. 调整视角高度、手部 IK、抓取／攀爬距离、地面检测等与体型相关的参数。
3. 按玩家网络 ID 同步倍率和剩余时间，处理后加入玩家、死亡、复活和切换场景。
4. 放大及恢复正常体型前检查空间，避免卡进墙体。

可先从 0.75 倍／1.25 倍进行独立原型验证；仅改 transform.localScale 不足以完成可靠的联机体型效果。

## 已有状态可用于药水原型

`Affliction_Invincibility`（无敌）、`Affliction_FasterBoi`（移动／攀爬速度）、`Affliction_LowGravity`（低重力）、`Affliction_Blind`（失明）、`Affliction_InfiniteStamina`（无限体力）等已有原生状态。

未来开发时仍需核对每个状态的构造参数、叠加规则、到期清理与网络序列化。原版没有的药水效果要实现自己的计时、同步和恢复逻辑。
